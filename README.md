# signalbench

[![CI](https://github.com/nishsm/signalbench/actions/workflows/ci.yml/badge.svg)](https://github.com/nishsm/signalbench/actions/workflows/ci.yml)

**Research question:** Can a small task-tuned open model match an API classifier on financial
sentiment, and does better classification translate into a useful stock-return signal?
**Status: implementation and validation in progress. No complete benchmark or backtest has run.**
Headline F1, API cost, IC and net Sharpe are unmeasured. A null return result is an acceptable
finding. Every reported research number must be generated by a repository script.

Author: Nishanth (Nish) Madthila, Carnegie Mellon MS Information Systems Management.

Preliminary CPU baselines can be reproduced with `make bench CONFIG=configs/cpu.yaml`;
these do not answer the full model-comparison or trading questions.

## Results and evidence

[Generated results](results/README.md) and [resume evidence](RESULTS_FOR_RESUME.md) distinguish
measured output from pending experiments. `make report` renders these from `benchmark.csv`,
`significance.json` and `backtest.csv`; it never fills missing results with synthetic estimates.
The root README is the protocol and navigation; measured tables and plots live under results.
Do not treat the badge as evidence of a GitHub run until this repository has been published.

The full benchmark compares a majority prior, training-only TF-IDF logistic regression,
ProsusAI/finbert, pinned GPT-4o-mini zero-shot/fixed few-shot/semantic RAG few-shot,
Qwen2.5-3B-Instruct base and its QLoRA adapter. Validation selects the API approach;
test results never select prompts. API outputs have discrete sentiment scores, not calibrated
probabilities. FinBERT and local models expose class probabilities; reliability diagrams
and ECE apply to those models. Local costs exclude hardware/electricity; throughput metadata
identifies the actual machine. Cached API timing preserves original service time.

## Methodology

Read [the research protocol](docs/PROTOCOL.md) before running experiments.

- Normalize, deduplicate connected near-duplicate components using MinHash and a character-cosine audit before stratified splitting;
  exclude conflicting-label components. Store split IDs and immutable HF revisions.
- PhraseBank all-agree is primary. The secondary experiment uses only the nonoverlapping
  75-agree supplement. Twitter's published validation CSV is OOD evaluation only.
- Demonstrations and retrieval use training examples only. All classifiers use the same
  ordered labels: negative, neutral, positive. Signed score is P(positive)−P(negative)
  when probabilities exist. API labels map to −1/0/+1.
- Keep SEC acceptance timestamps with timezone. A filing before the scheduled open maps
  to that session; at/after open maps to the next session. NYSE holidays, early closes and
  daylight saving time come from the exchange calendar. Portfolio entry is strictly later
  than publication. Descriptive prior-close event returns are distinct from executable PnL.
- Study market-adjusted day-zero and +1:+5/+1:+20 returns, date-clustered event means,
  monthly Spearman IC, and overlapping cohorts held for five sessions. Bucket boundaries
  use earlier dates only. Costs apply per side to traded notional; report cost sensitivities.
- Do not silently omit missing prices for held positions. Event exclusions and acquisition
  failures have coverage reports. No fabricated delisting returns or forward-filled prices.

**Pitfalls and limitations:** A current constituent universe is survivorship-biased. Supply
`data/universe.csv` with CIK, ticker, as-of date and membership source; the sample CSV in docs
is a format example, not a research universe. Free Yahoo prices are not an institutional
point-in-time security master, and may omit delisted companies. Borrow fees, locate constraints
and detailed auction slippage remain unmodeled. Earnings/non-earnings and early/late subsets
are exploratory. Historical market-cap robustness is unavailable until point-in-time caps
are supplied; current caps cannot substitute.

**LLM look-ahead contamination:** Internet pretraining may include later corporate news and
returns. Verified training cutoffs enable a separate post-cutoff subset; unknown cutoffs are
marked unavailable, never guessed from release dates. Fine-tuning on older PhraseBank data
does not remove this risk. FinBERT was trained on PhraseBank and its in-domain score is a
contaminated reference, not an independent generalization estimate. Cluster-by-date standard
errors do not address all same-firm serial dependence, multiple testing or overlapping windows.
The best observed trading Sharpe is exploratory and cannot establish deployable alpha.

## Reproduce

Python 3.11–3.13. Use a virtual environment; direct dependencies are pinned in `pyproject.toml`.
A CPU resolved environment snapshot is written to `requirements-cpu.lock` after verification.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
pre-commit install
cp .env.example .env
make data
# Mac: optional FinBERT/API inference; Linux RTX 4060: train and run Qwen.
pip install -e '.[ml,train]'
make finetune
make bench
# Review the complete benchmark with Nish before collecting the research universe.
# Set edgar.scaleup_approved=true only after that checkpoint, and supply universe.csv.
make universe  # current constituent proxy, explicitly survivorship-biased
make edgar
make prices
make all
```

`make all` reruns data, benchmark, scoring, backtest and reports against local caches. Acquisition
and training are explicit stages so a cached rerun never launches a new GPU training job.
It fails clearly if required caches/adapter are missing. On a fresh checkout use the stages
above. Configurable paths, seed, prices, model and cost assumptions are in `configs/default.yaml`.
Each output has an adjacent config/commit/timestamp sidecar; raw data, price files, caches and
weights are gitignored. Exact reproduction also needs the cached raw API responses because
temperature zero plus a pinned snapshot does not guarantee provider-side determinism.

The API ledger reserves a conservative per-request cost before calling, caches raw responses
and actual token usage in SQLite, and enforces one shared budget across stages. A crash after
reservation requires reconciling that entry with provider usage before retrying; it is never
silently reset. No automatic network retry can duplicate a billed request. A large filing cost
estimate triggers seeded API subsampling while local models cover the full set. An estimate
above budget or suspicious OOD F1/Sharpe requires review with Nish before reporting.

QLoRA uses NF4, batch size one, accumulation, checkpointing, paged optimizer, bf16 where
supported and fp16 otherwise, evaluation checkpoints and validation early stopping. Adapter-only
checkpoints resume interrupted training. The target label is the completion; inference compares
full label token log-likelihoods and normalizes across the same three classes.
Hardware/runtime measurements are pending until those actual runs; no RTX speed is inferred
from a Mac. Tests never download models or contact APIs:

```bash
ruff check .
ruff format --check .
pytest -q
```

Set `hub.repo_id` after training/evaluation and run `make publish` to upload the adapter, measured
model card, base license and required notices. Publication needs a valid HF token. No adapter
has been trained or uploaded yet. GitHub publication requires an authenticated `gh` session;
the expected repository is `nishsm/signalbench`.
